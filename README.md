# 嘉桦1.1（Jiahua-1.1）

只用 **Python + PyTorch**、不依赖 `transformers` 的中英双语问答模型。
模型结构、训练、推理全部自己写，训练完只留一个 `.pt` 权重文件。

```
下载代码  ->  双击训练脚本  ->  双击问答脚本  ->  开始提问（中文 / 英文都行）
```

| 版本 | 主力参数量 | 一句话说明 |
|---|---|---|
| 嘉桦1.1 | **1.5B**（实测 1,507,855,104） | 修好"你是谁"的回答，中英双语，新增 int8 推理 |
| 嘉桦1.0 | 0.75B（实测 755,148,288） | 第一版，只有中文，问答偏简单 |

**这次 1.1 改了什么**

1. **修好身份问答**：问"你好，你是谁？"，答"你好，我是由嘉桦自主研发的AI模型，是一个纯文本模型。"
2. **升级到 1.5B**：`configs/1.5b.json`，25 层 / 2304 维 / 18 头（GQA 6 组 K/V）/ SwiGLU 6144。
3. **中英双语**：语料和问答数据都加了英文，你用英文问，它就用英文答。
4. **能上 8G 内存**：新增 `--quant8`，1.5B 权重从约 6GB 压到约 1.7GB，8G 内存笔记本能跑。

## 一、下载后三步走（最省事）

1. `git clone https://github.com/plpy6636-ABC/Jiahua-1.1.git`（或点 Code → Download ZIP 解压）
2. 双击 **`一键训练1.5B.bat`** —— 自动建词表、预训练、问答微调
3. 训练完双击 **`一键问答1.5B.bat`** —— 直接开聊，输入 `退出` 结束

> 想先花 3 分钟看看整条流程长什么样：双击 `一键试跑.bat`（357 万参数的小模型，跑完自动提问）。

手动命令也一样（Windows 上 `py -3.13`，macOS/Linux 换成 `python3`）：

```bash
pip install torch                      # 只有这一个依赖

py -3.13 tokenizer.py build --data data/corpus.txt data/qa.jsonl --out tokenizer.json
py -3.13 train.py --config configs/1.5b.json --data data/corpus.txt --out_dir out_1.5b \
   --max_steps 20000 --batch_size 1 --grad_accum 16
py -3.13 sft.py   --ckpt out_1.5b/ckpt_last.pt --data data/qa.jsonl --out_dir out_1.5b_sft \
   --max_steps 3000 --batch_size 2 --seq_len 512 --lr 1e-4
py -3.13 chat.py  --ckpt out_1.5b_sft/ckpt_final.pt --quant8
```

## 二、硬件要求（照实说）

| 你要做的事 | 最低配置 | 建议配置 | 说明 |
|---|---|---|---|
| **问答（推理）int8** | **8G 内存 + 不需要显卡** | 16G 内存 | 权重约 1.7GB（线性层 1 字节/参数，词向量表仍 fp32），8G 内存装得下；CPU 出字速度大约 1~5 字/秒 |
| 问答（推理）不量化 | 10G 内存 | 16G 内存 | 权重约 6GB，8G 内存会很吃紧 |
| 问答（推理）用显卡 | 4G 显存 | 6G 以上 | fp16 权重约 2.8GB |
| **训练 1.5B（全参数）** | 16G 显存（batch=1 + 梯度累积） | **24G 显存** | 参数+梯度+Adam 状态约 19.7GB 起，再加激活值 |

**关于"8G 内存 + 1G 显存"**：这个组合可以跑，但只能**推理**，而且要走 CPU：

- 8G 内存 ✅ 能装下 int8 的 1.5B（约 1.7GB）
- 1G 显存 ❌ 装不下 1.5B（fp16 就要 2.8GB，int8 也要 1.5GB），`chat.py` 检测到显存小于 4GB 会自动退回 CPU 并在屏幕上告诉你
- 训练 ❌ 1G 显存训不了 1.5B，需要 20GB 以上显存的显卡

## 三、和别的 1.5B 模型比一比

> 只对比**结构、体积、依赖**这些硬指标（数据取自各模型公开说明），**不对比跑分**。
> 嘉桦1.1 是个人自研、语料量小得多，能力上**明显弱于**同参数量的工业模型，别拿它当同级别替代。

| 项目 | **嘉桦1.1** | Qwen2.5-1.5B | TinyLlama-1.1B | GPT-2 XL |
|---|---|---|---|---|
| 参数量 | **1.508B** | 1.54B（非嵌入 1.31B） | 1.1B | 1.542B |
| 层数 | 25 | 28 | 22 | 48 |
| 隐藏维度 | 2304 | 1536 | 2048 | 1600 |
| 注意力 | GQA（18 头 / 6 组 K/V） | GQA（12 头 / 2 组 K/V） | GQA（32 头 / 4 组） | MHA |
| 上下文长度 | 1024 | 32768 | 2048 | 1024 |
| 词表大小 | 4 万（分词器实测约 5 百字符） | 151936 | 32000 | 50257 |
| 中文 | 原生支持（字符级分词） | 原生支持 | 弱 | 不支持 |
| 依赖 | **只要 torch** | transformers 等 | transformers 等 | transformers 等 |
| 许可证 | 本仓库自定 | Apache-2.0 | Apache-2.0 | Modified MIT |
| 定位 | 自己手写一遍、看懂每个数 | 通用生产可用 | 英文小模型基线 | 2019 年的老基线 |

**这张表想表达的**：嘉桦1.1 的结构和主流 1.5B 是同一套（Decoder-only + RMSNorm + RoPE + SwiGLU），参数量也落在同一档；差别在于词表是字符级、上下文只有 1024、语料是自己攒的小语料，所以**它更像"解剖用的模型"，而不是"干活的模型"**。

## 六、实测问答（小模型验证版，int8）

1.5B 需要显卡才能训练，所以这组输出用的是 `configs/tiny.json`（357 万参数）在同一套代码上跑出来的，
预训练 500 步 + 问答微调 1500 步，**验证的是代码路径和中英文数据，不代表 1.5B 的实际水平**：

```
用户：你好，你是谁？
助手：你好，我是由嘉桦自主研发的AI模型，是一个纯文本模型。
[用时 0.1s，生成 27 字]

用户：who are you
助手：Hello, I am an AI model independently developed by Jiahua. I am a text-only model.
[用时 0.2s，生成 82 字]
```

注意：小模型微调步数少了会答偏（试过 900 步时英文会串），加到 1500 步才稳；1.5B 建议至少 3000 步。

## 七、常见问题

**问：为什么词表写 4 万，分词器只有 5 百多字符？**
答：配置里的 4 万是"预留座位"，实际语料只用到五百多个字符。空着的行不参与梯度，不影响训练，但会让总参数量看起来是 1.5B。想真装满，得换几百 MB 以上的语料。

**问：英文为什么是一个字母一个 token？**
答：这套分词器是字符级的，中文一个字刚好是一个词，英文就会拆成字母。能用，但费 token、费算力。要做正经英文，得换 BPE/子词分词器（本仓库没做）。

**问：训练很久没反应？**
答：1.5B 在 CPU 上训练基本不用想，必须显卡。想先看效果就 `一键试跑.bat`。

**问：能不能继续加数据？**
答：能。笔记、小说、问答都行：文本追加到 `data/corpus.txt`，问答追加到 `data/qa.jsonl`（一行一个 `{"q": "...", "a": "..."}`），重跑训练脚本即可；`--resume out_1.5b/ckpt_last.pt` 能接着上次继续。

**问：权重在哪？**
答：仓库不带权重（太大）。训练完在 `out_1.5b_sft/ckpt_final.pt`，单个文件，拷走就能用。
